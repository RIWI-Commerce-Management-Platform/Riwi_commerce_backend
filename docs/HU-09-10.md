## What was implemented

### HU-09 — Password recovery

- `auth.ts` configures `emailAndPassword.sendResetPassword`, a 1-hour token and `revokeSessionsOnPasswordReset`.
- `POST /auth/forgot-password` `{ email, redirectTo? }` (public). Always answers 200, so it can't be used to find out which emails exist. `redirectTo` defaults to `FRONTEND_URL/reset-password`.
- The email link goes to Better Auth (`/api/auth/reset-password/:token`), which redirects to `redirectTo?token=...`. The frontend page then calls `POST /auth/reset-password` `{ token, newPassword }` (public; 400 on an invalid or expired token).
- `infrastructure/password-reset-mailer.ts` sends the email through **Amazon SES** (`@aws-sdk/client-sesv2`) when `AWS_SES_FROM_EMAIL` is set. Without it, the link is written to the server log (local development).

### HU-10 — Microsoft 365

- `auth.ts` enables the `microsoft` social provider only when `MICROSOFT_CLIENT_ID` and `MICROSOFT_CLIENT_SECRET` are set (`MICROSOFT_TENANT_ID` defaults to `common`).
- `POST /auth/microsoft` `{ callbackURL?, errorCallbackURL? }` (public) returns `{ url }`; the frontend redirects the browser there. The state cookie Better Auth sets is forwarded. Microsoft returns to `BETTER_AUTH_URL/api/auth/callback/microsoft`, which creates the session and redirects to `callbackURL` (default `FRONTEND_URL`). New Microsoft users get the `ASESOR` role.
- Without the variables the endpoint answers 400 "Provider not found".

### Setup still needed in AWS / Azure

- SES: verify the sender (domain or address), leave the sandbox (or verify recipients), and set `AWS_SES_FROM_EMAIL`. The instance role or keys need `ses:SendEmail`.
- Azure: register an app, add the redirect URI `${BETTER_AUTH_URL}/api/auth/callback/microsoft`, and set the three `MICROSOFT_*` variables.
