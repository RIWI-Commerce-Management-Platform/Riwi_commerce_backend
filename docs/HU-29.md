# HU-29 — Shared file storage service

**Owner:** Carlos · **Epic:** E5 — Cotizaciones, pedidos y archivos S3 · **Priority:** Alta
**Source:** `docs/Comercial360_Historias_y_Reparto_v2.pdf`

> As a dev, I want a shared file storage service, so every module uploads to S3 the same way.

## Acceptance criteria

| Criterion | Status |
|---|---|
| `FileStorageService` interface + S3 implementation in infrastructure | ✅ Done |
| The DB stores the file key (not the file itself) | ✅ Done |
| Download via a temporary signed URL | ✅ Done |
| Size limit and allowed file types enforced | ✅ Done |

## What was implemented

### 1. `FileStorageService` — the shared port

`src/shared/file-storage/` is a cross-cutting module, not a full business module: it has `domain/` and `infrastructure/` only (no `application/`/`presentation/`, since it exposes no use cases or HTTP endpoints of its own).

- **Domain** — `FileStorageService` (`domain/file-storage.service.ts`), an abstract class with `upload(options)`, `getPresignedUrl(key, expiresInSeconds?)`, `delete(key)`; `UploadFileOptions` / `UploadedFileResult` interfaces; `FileSizeExceededError` and `InvalidFileTypeError` domain errors.
- **Infrastructure** — `S3FileStorageService` (`infrastructure/s3-file-storage.service.ts`) implements the port using `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner`.
- **Wiring** — `file-storage.module.ts` binds `{ provide: FileStorageService, useClass: S3FileStorageService }` and exports `FileStorageService`; imported into `AppModule` so any module can inject the port.

The acceptance criteria text places the interface in "the application layer"; it actually lives in `domain/`, matching the port pattern the rest of the codebase already uses (`ZoneRepository`, `QuoteRepository` are domain-layer abstract classes too) — a wording difference, not a functional gap.

### 2. Upload, download, delete

- `upload()` builds a collision-resistant key (`<folder>/<timestamp>-<uuid>-<sanitized filename>`), puts the object via `PutObjectCommand`, and returns `{ key, originalName, mimetype, size }`.
- `getPresignedUrl(key, expiresInSeconds = 3600)` returns a time-limited signed `GetObjectCommand` URL — the default expiry is 1 hour.
- `delete()` removes the object via `DeleteObjectCommand`.

### 3. Size and type limits

`S3FileStorageService.validateFile()` runs before any upload:
- **Size:** 10MB (`maxFileSizeInBytes`), throws `FileSizeExceededError` with the limit in MB.
- **Type:** an explicit MIME allowlist (`application/pdf`, `image/jpeg`, `image/png`, `image/webp`, `text/csv`, XLS/XLSX), throws `InvalidFileTypeError` naming the rejected type and the allowed list.

Both error paths are unit-tested in `infrastructure/s3-file-storage.service.spec.ts`.

### 4. Config

`src/shared/config/configuration.ts` adds an `aws` block (`region`, `bucketName`, `accessKeyId`, `secretAccessKey`) read from `AWS_REGION` / `AWS_S3_BUCKET` / `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`, documented in `.env.example`. `S3Client` is only given explicit credentials when both key env vars are set, so it falls back to the default AWS credential chain (IAM role on EC2) otherwise — matching HU-02's "no keys in the repo, IAM role or env vars" requirement.

### 5. First consumer: quotes

`quotes.document_key` (`src/modules/quotes/infrastructure/quote.orm-entity.ts`) is where a module stores the S3 key this service returns — see [HU-30](./HU-30.md). `QuotesModule` doesn't import `FileStorageModule` yet; it only persists whatever key the client sends, it doesn't call `.upload()` itself.

## Verified in this environment

- `npm run build` — clean.
- `npm run lint` — clean (`oxlint --type-aware`).
- `npm run test` — unit tests pass, including the size/type validation cases.

## Not yet verified

- Real connectivity to S3 (no AWS credentials or bucket in this environment) — `PutObjectCommand`/`GetObjectCommand`/`DeleteObjectCommand` are exercised only indirectly through the mocked test; `validateFile()` runs before any network call, so the rejection tests don't need a real bucket.

## Explicitly out of scope

- An HTTP upload endpoint (multipart file upload) that actually calls `FileStorageService.upload()` — that's HU-31 (quotes document upload), not yet implemented.
- `ActivityLogService`, the other abstract service named alongside `FileStorageService` in the architecture doc — still not implemented (see root `CLAUDE.md`).
