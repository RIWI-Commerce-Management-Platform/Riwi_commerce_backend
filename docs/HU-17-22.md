# HU-17 to HU-22 — Route planning

**Owner:** Alejandro · **Epic:** E3 — Route planning · **Priority:** Alta (HU-17 to HU-20), Media (HU-21), Baja (HU-22)
**Source:** `docs/Comercial360_Historias_y_Reparto_v2.pdf`. The owner's detailed write-up (in Spanish) is `docs/EPIC-E3-planeacion-rutas-alejandro.md`.

> - **HU-17:** As a regional director, I want to create a route with its general data, so I can plan the week.
> - **HU-18:** As a regional director, I want to add clients to the route and order the stops, so I can define the itinerary.
> - **HU-19:** As a regional director, I want to see the route on a map, so I can validate the itinerary.
> - **HU-20:** As a regional director, I want to assign the route to an advisor, so it appears on their agenda.
> - **HU-21:** As a regional director, I want to see the assigned routes, so I can control the operation.
> - **HU-22:** As a regional director, I want to see the route's estimated distance and time.

## What was implemented

Delivered in commit `be33ffe`, all in `src/modules/routes/`.

### 1. Domain

- `Route` aggregate: `addStop`, `removeStop` (renumbers the remaining stops), `reorderStops`, `assignAdvisor` (requires at least one stop and moves to `ASSIGNED`), `updateMetrics`, `activate`/`deactivate`.
- `RouteStop`: `clientId`, `visitOrder`, `suggestedTime`, `estimatedDurationMinutes`.
- Enums: `RouteStatus` (`DRAFT`, `ASSIGNED`, `INACTIVE`), `DayOfWeek`, `RouteFrequency` (`WEEKLY`, `BIWEEKLY`, `MONTHLY`).
- `RouteRepository` port and domain errors, including `RouteNameAlreadyExistsError` and `UnauthorizedZoneError`.

### 2. Application

- **Use cases:** create/update draft, add/remove/reorder stops, assign advisor, calculate metrics, find (paginated), get by id, toggle status.
- **Recalculation:** adding, removing or reordering a stop recalculates the route's distance and duration.
- **Zone security:** a `DIRECTOR_REGIONAL` can act only on routes in their zone, and listing is forced to that zone. `ADMIN` is unrestricted.
- **Cross-module ports** in `application/ports/`:
  - `RouteClientReaderPort`: client coordinates and zone, from the clients module.
  - `VisitSchedulerPort`: creates visits in the visit module (E4).
  - `RouteDistanceCalculatorPort`: distance and duration calculation.

### 3. Infrastructure

- `RouteOrmEntity` and `RouteStopOrmEntity`. Each client can appear only once per route (unique `(route_id, client_id)`).
- Migration `1792670000000-CreateRoutesTables.ts`.
- `TypeOrmRouteRepository` saves a route and its stops in a single transaction.
- `TypeOrmRouteClientReaderAdapter` reads clients through `ClientRepository`.
- `HaversineRouteDistanceCalculatorAdapter`:
  - Distance: Haversine between consecutive stops, multiplied by 1.3 for urban roads.
  - Time: travel at 25 km/h plus each stop's attention time.
  - OSRM isn't used.
- `TypeOrmVisitSchedulerAdapter`:
  - Generates dates from `startDate` matching the route's weekday, stepping by the route's frequency.
  - Without an `endDate`, it schedules 4 weeks ahead.
  - Inserts one `PENDING` visit per stop per date, at the stop's suggested time.

### 4. Presentation

`RoutesController` uses `@UseGuards(SessionGuard, RolesGuard)`. `RolesGuard` loads `role` and `zoneId` from the DB into `request.user`, and the zone checks use those values.

| Method | Path | Story | Roles |
|---|---|---|---|
| `POST` | `/routes` | HU-17 | Director, Admin |
| `PATCH` | `/routes/:id` | HU-17, HU-21 | Director, Admin |
| `POST` | `/routes/:id/stops` | HU-18 | Director, Admin |
| `DELETE` | `/routes/:id/stops/:clientId` | HU-18 | Director, Admin |
| `PATCH` | `/routes/:id/stops/reorder` | HU-18, HU-19 | Director, Admin |
| `GET` | `/routes/:id` | HU-19, HU-21 | Director, Admin, Advisor |
| `POST` | `/routes/:id/assign` | HU-20 | Director, Admin |
| `GET` | `/routes` | HU-21 | Director, Admin, Advisor |
| `PATCH` | `/routes/:id/status` | HU-21 | Director, Admin |
| `POST` | `/routes/metrics/calculate` | HU-22 | Director, Admin |

`RouteResponseDto` includes `stopsCount`, `totalDistanceKm` and `estimatedDurationMinutes` (the HU-22 summary). Each stop includes the client's name, address, municipality and coordinates (HU-19).

## Follow-up fixes

- **Validation pipe.** `RoutesController` now applies `ValidationPipe({ whitelist: true, transform: true })`. Invalid bodies get the documented 400, and `page`/`limit` on `GET /routes` work (before, the plain query object had no `parsedPage` getter, so every request returned page 1).
- **`isActive` filter.** `FindRoutesQueryDto.isActive` used `@Type(() => Boolean)`, which turns the string `"false"` into `true`. It now uses an explicit `'true'`/`'false'` transform.
- **Reassignment.** `TypeOrmVisitSchedulerAdapter.scheduleVisitsForRoute` first deletes the route's `PENDING` visits, so reassigning a route replaces the old schedule instead of duplicating it. Visits already in progress or done are kept.
- **Tests.** Added coverage for:
  - the metric recalculation paths in remove/reorder stop;
  - every weekday and frequency in the scheduler;
  - a director moving a route to another zone;
  - the controller's error translation.

## Known leftover

`POST /routes/:id/assign` can't check that `advisorId` exists or belongs to the zone: advisors are still the temporary numeric id from `src/shared/auth/` and have no table of their own.
