> As an advisor, I want to create a quote with products, so I can send it to the client.

## What was implemented

### 1. `quotes` module

Follows the standard 4-layer shape (`src/modules/quotes/`):

- **Domain** — `Quote` and `QuoteItem` entities, `QuoteStatus` enum (`DRAFT`/`SENT`/`APPROVED`/`REJECTED`), `QuoteDao` port, and `domain/errors/`: `EmptyQuoteItemsError`, `InvalidQuoteItemValuesError`, `QuoteNotFoundError`.
- **Application** — `CreateQuoteUseCase`, `GetQuoteByIdUseCase`, `CreateQuoteCommand`/`CreateQuoteItemCommand` (small local input types, not the request DTO).
- **Infrastructure** — `QuoteOrmEntity` / `QuoteItemOrmEntity` (table `quotes` + `quote_items`, FK with `onDelete: CASCADE`), `QuoteMapper`, `TypeOrmQuoteDao`, migration `1792430815290-CreateQuotesTables`.
- **Presentation** — `QuotesController`: `POST /quotes`, `GET /quotes/:id`; `CreateQuoteDto`/`CreateQuoteItemDto` request DTOs, `QuoteResponseDto`/`QuoteItemResponseDto` response DTOs, Swagger-documented.

### 2. Consecutive numbering and calculations

`CreateQuoteUseCase.execute()`:
- Validates the command: rejects an empty `items` array (`EmptyQuoteItemsError`) and any item with `quantity <= 0` or `unitPrice < 0` (`InvalidQuoteItemValuesError`).
- Asks the repository for the next `COT-####` number, computes each item's subtotal (`quantity * unitPrice`, rounded to 2 decimals) and the quote's subtotal/total (sum of item subtotals; no taxes/discounts in this story), then persists the `Quote` with its `QuoteItem`s via `QuoteDao.save()`.
- Covered by `application/create-quote.use-case.spec.ts` (empty items, invalid quantity, negative price, successful calculation).

### 3. Race-condition fix in consecutive numbering

The first implementation of `generateNextQuoteNumber()` read the latest `quotes` row (`ORDER BY created_at DESC LIMIT 1`) and incremented its numeric suffix in application code — two concurrent `POST /quotes` requests could both read the same "latest" row before either committed and generate the same number, which would then collide against the `quote_number` unique constraint.

Fixed by backing the generator with a dedicated Postgres sequence (`quote_number_seq`, created in the same migration) instead of a read-then-increment:

```ts
// src/modules/quotes/infrastructure/typeorm-quote.dao.ts
async generateNextQuoteNumber(): Promise<string> {
  const [{ nextval }] = await this.ormRepository.query<{ nextval: string }[]>(
    "SELECT nextval('quote_number_seq') AS nextval",
  );
  return `COT-${nextval.padStart(4, '0')}`;
}
```

A sequence hands out a unique, monotonically increasing value per call with no locking and no collision window, even across rolled-back transactions.

### 4. IDs moved from UUID to DB-generated auto-increment

Per the team's updated convention (`clients` on `feature/HU-11` set the precedent — see the `CLAUDE.md` "ID strategy" note), `Quote.id`, `QuoteItem.id`, and `Quote.clientId` moved from client-generated UUID strings to DB-generated auto-increment integers:

- `QuoteOrmEntity`/`QuoteItemOrmEntity`: `@PrimaryColumn('uuid')` → `@PrimaryGeneratedColumn()`; `quote_id`/`client_id` columns: `uuid` → `int`.
- `Quote`/`QuoteItem` domain entities: `id` is now `id?: number`, unset until the row is inserted; `CreateQuoteUseCase` no longer calls `randomUUID()`.
- `QuoteMapper.toOrm()` only assigns `orm.id` when `domain.id !== undefined`; a new quote's items link to their parent via the ORM relation (`itemOrm.quote = orm`) rather than a pre-known `quoteId`, so TypeORM's cascade insert sets the `quote_id` FK once the parent row gets its generated id.
- `GET /quotes/:id` uses `ParseIntPipe`; response DTOs read `entity.id!` (safe — an entity only reaches a response DTO once persisted).
- The migration (`1792430815290-CreateQuotesTables`) was edited in place rather than adding a follow-up migration, since it had not yet been run against any shared database.

### 5. S3 document reference

`quotes.document_key` (nullable `varchar`) stores the S3 key for an attached quote document — the field [HU-29](./HU-29.md)'s `FileStorageService` is meant to populate. The use case accepts whatever `documentKey` the client sends; it doesn't call `FileStorageService` itself (see HU-29, "Explicitly out of scope").
