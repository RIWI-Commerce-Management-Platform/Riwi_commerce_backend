# HU-12 — Search and filter clients

**Owner:** Yesid · **Epic:** E2 — Clients, catalogs and activity log · **Priority:** Alta
**Source:** `docs/Comercial360_Historias_y_Reparto_v2.pdf`

> As an advisor, I want to search and filter clients, so I can find them quickly.

## Acceptance criteria

| Criterion | Status |
|---|---|
| Search by NIT, business name or commercial name | ✅ Done |
| Filters by zone, client type, municipality and potential | ✅ Done |
| Paginated results | ✅ Done |

## What was implemented

Delivered in commit `0728a36` together with HU-11.

### 1. Domain

- `ClientFilterCriteria` (`src/modules/clients/domain/client-filter.criteria.ts`): `search`, `zoneId`, `clientTypeId`, `potentialId`, `municipality`, `isActive`, `page`, `limit`.
- `ClientRepository.findPaginated(criteria)` returns a `PaginatedResult<Client>` from `src/shared/pagination/`.

### 2. Application

- `FindClientsUseCase` delegates to the repository port.

### 3. Infrastructure

`TypeOrmClientRepository.findPaginated` builds a query with `createQueryBuilder('client')`:

- `search`: case-insensitive partial `LIKE` over `nit`, `business_name` and `commercial_name`.
- `zoneId`, `clientTypeId`, `potentialId`: exact match.
- `municipality`: case-insensitive exact match.
- `isActive`: exact match (an extra filter beyond the spec).
- Ordered by `created_at DESC`; `page` defaults to 1, `limit` to 10.

### 4. Presentation

- `GET /clients` in `ClientsController`, with `FindClientsQueryDto`, which extends the shared `PaginationQueryDto`.
- The DTO exposes getters (`parsedZoneId`, `parsedClientTypeId`, `parsedPotentialId`, `parsedIsActive`, `parsedPage`, `parsedLimit`) that convert the raw query strings into numbers and booleans. `parsedLimit` caps the page size at 100.
- The response is a `PaginatedClientResponseDto` that includes each client's coordinates.
- The endpoint requires a session (global `SessionGuard`). There is no role restriction.

## Verified in this environment

- `npx vitest run src/modules/clients`: all unit specs pass.

## Fixed: filters and pagination were ignored over HTTP

`ClientsController` applied no pipe, so Nest passed `@Query()` as the plain `req.query` object. The DTO's `parsed*` getters didn't exist at runtime: zone, type, potential and `isActive` were ignored, and every request returned page 1 with 10 items. The unit spec hid this because it built the DTO with `new FindClientsQueryDto()`.

- `GET /clients` now uses `@Query(queryValidationPipe())` from `src/shared/pagination/query-validation.pipe.ts` (`whitelist` + `transform`).
- `FindClientsQueryDto` and the shared `PaginationQueryDto` have `@IsOptional()` on each field, so `whitelist` keeps them.
- `src/shared/pagination/query-validation.pipe.spec.ts` checks this over real HTTP with supertest.
- The same fix applies to `GET /quotes` and `GET /orders` (HU-34), which had the same bug.
