## What was implemented

### 1. Global validation (`src/main.ts`)

`app.useGlobalPipes(new ValidationPipe({ whitelist: true, transform: true }))`. With `whitelist`, a field without a class-validator decorator is stripped, so every request DTO that had none got decorators: `CreateClientDto`, `UpdateClientDto`, `ToggleClientStatusDto`, `CreateClientContactDto`, `UpdateClientContactDto`, `CreateQuoteDto`, `CreateQuoteItemDto` and `AssignUserRoleDto`. Invalid bodies (empty NIT, bad email, negative quantity, ...) now return 400 instead of reaching the use case.

Controllers keep their own `@UsePipes(...)` and `queryValidationPipe()`; running the pipe twice is harmless.

> The `dashboard` module (HU-35, Valery) is not registered yet. Its `DashboardFiltersDto` has no class-validator decorators, so its fields would be stripped by the global pipe once it is registered.

### 2. Global exception filter (`src/shared/http/all-exceptions.filter.ts`)

Every error answers with the same body:

```json
{ "statusCode": 404, "error": "NOT_FOUND", "message": "Client with id \"9\" was not found", "path": "/clients/9", "timestamp": "2026-10-24T17:39:40.478Z" }
```

- `HttpException`s keep their status and message (validation messages stay an array).
- Domain errors that a controller didn't map are classified by name: `*NotFoundError` → 404, `*AlreadyExistsError`/`*AlreadyAssignedError`/`*AlreadyConvertedError` → 409, `Invalid*Error`/`Empty*Error` → 400.
- Anything else is logged with its stack and answered as a generic 500, so internal details never leak.

### 3. Swagger

`SwaggerModule.setup` is registered at `/docs` (local) and `/api/docs` (the URL in the spec, which also works behind the Nginx `/api` proxy).
