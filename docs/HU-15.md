**Owner:** Yesid · **Epic:** E2 — Clientes, catálogos y bitácora · **Priority:** Alta
**Source:** `docs/Comercial360_Historias_y_Reparto_v2.pdf`

> Como sistema, quiero registrar en bitácora cada acción sobre un cliente, para tener trazabilidad.

## What was implemented

### 1. Domain Layer (`src/modules/clients/domain/`)

- **`ClientHistory` entity:** Pure TypeScript model enforcing business invariants:
  - Validates positive integer `clientId`.
  - Requires non-empty `action` and `description`.
  - Holds `userId` (supports string Better Auth user IDs or numeric advisor IDs), `entityType`, `entityId`, `metadata` (JSON payload for contextual details), and `createdAt`.
  - Provides a static `ClientHistory.create()` factory helper.
- **`ClientHistoryRepository` port:** Abstract class defining persistence contracts:
  - `save(history: ClientHistory): Promise<ClientHistory>`
  - `findByClientId(clientId: number, criteria?: ClientHistoryFilterCriteria): Promise<PaginatedResult<ClientHistory>>`
  - `findRecent(limit?: number): Promise<ClientHistory[]>`
  - `findById(id: number): Promise<ClientHistory | null>`
- **`ClientHistoryFilterCriteria`:** Standard interface for dynamic filtering (`page`, `limit`, `action`, `startDate`, `endDate`).
- **`ClientHistoryNotFoundError`:** Explicit domain error.

### 2. Application Layer (`src/modules/clients/application/`)

- **`RecordClientActivityUseCase`:** Validates client existence through `ClientRepository.findById()`, instantiates a domain `ClientHistory`, and persists it through `ClientHistoryRepository`.
- **`GetClientHistoryUseCase`:** Validates client existence and retrieves paginated chronological audit logs ordered descending by `createdAt`.
- **`GetRecentInteractionsUseCase`:** Retrieves global recent interactions across clients to populate dashboard activity feeds ("Últimas interacciones").
- **Client Module Integrations:** Injected `ActivityLogService` as an optional dependency into `CreateClientUseCase` (`client.created`), `UpdateClientUseCase` (`client.updated`), and `ToggleClientStatusUseCase` (`client.activated` / `client.deactivated`) without breaking legacy constructor calls in existing unit tests.

### 3. Shared Activity Log Port & Persistent Implementation (`src/shared/activity-log/`)

- **Port (`ActivityLogService`):**
  - Updated abstract class to maintain complete backwards compatibility with Camilo's visit module (`record(entry: ActivityLogEntry): Promise<void>`).
  - Added native support for the project specification method `register(clientId, action, description, user, metadata)`.
- **`TypeOrmActivityLogService`:**
  - Concrete adapter replacing `NoopActivityLogService`.
  - Injects TypeORM `Repository<ClientHistoryOrmEntity>`.
  - Automatically resolves `clientId` from `entry.clientId`, `entry.metadata.clientId`, or `entry.entityType === 'client' ? entry.entityId : null`.
  - Generates sensible fallback descriptions if omitted (`${action} on ${entityType} #${entityId}`).
  - Persists directly into `client_histories`.
- **`ActivityLogModule`:**
  - Wired `{ provide: ActivityLogService, useClass: TypeOrmActivityLogService }`.
  - Exported and registered in `app.module.ts` and `clients.module.ts`.

### 4. Infrastructure Layer (`src/modules/clients/infrastructure/`)

- **`ClientHistoryOrmEntity`:** Mapped to table `client_histories` with TypeORM decorators:
  - `id`: integer auto-increment primary key.
  - `client_id`: integer foreign key referencing `clients(id)` with `ON DELETE CASCADE`.
  - `user_id`: `varchar(128)` nullable.
  - `action`: `varchar(100)` not null.
  - `description`: `text` not null.
  - `entity_type`: `varchar(50)` nullable.
  - `entity_id`: `varchar(50)` nullable.
  - `metadata`: `jsonb` nullable.
  - `created_at`: `timestamptz` default `now()`.
- **`ClientHistoryMapper`:** Pure bidirectional translation between `ClientHistory` and `ClientHistoryOrmEntity`.
- **`TypeOrmClientHistoryRepository`:** Implements `ClientHistoryRepository` using TypeORM `SelectQueryBuilder` with server-side pagination (`skip`/`take`), date range boundaries, and action filters.
- **Migration `1792650000003-CreateClientHistoriesTable`:**
  - Creates `client_histories` table with all columns and constraints.
  - Adds Postgres foreign key `client_id -> clients(id) ON DELETE CASCADE`.
  - Adds indices `IDX_client_histories_client_id` and `IDX_client_histories_created_at` for high-performance chronological lookups.

### 5. Presentation Layer (`src/modules/clients/presentation/`)

- **`ClientHistoryController` (`clients`):**
  - `GET /clients/interactions/recent`: Global feed for "Últimas interacciones".
  - `GET /clients/:clientId/history`: Paginated interaction history for a given client with query filter parameters (`page`, `limit`, `action`, `startDate`, `endDate`).
  - `POST /clients/:clientId/history`: Endpoint to log manual notes, observations, or call interactions.
- The manual endpoint takes `userId` from the authenticated Better Auth session via `@CurrentUser('id')`; the request body cannot choose the recorded actor.
- Visit and follow-up events use the same persistent adapter and include the visit's `clientId`, allowing them to be stored in the associated client's history.
- **DTOs with OpenAPI / Swagger:**
  - `CreateClientHistoryDto`: validated payload with Swagger examples.
  - `ClientHistoryResponseDto`: documented response schema with `fromDomain()` mapper.
  - `FindClientHistoryQueryDto`: inherits from `PaginationQueryDto` with sanitized parsing.
  - `PaginatedClientHistoryResponseDto`: Swagger schema definition for paginated responses.
