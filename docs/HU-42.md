## What was implemented

### Demo seed (`src/seeds/`)

`npm run seed:demo` builds the app and runs `dist/seeds/demo.seed.js`. It boots the Nest application context and loads everything **through the real use cases**, so it also exercises the whole flow:

- 1 admin, 1 regional director (Barranquilla Norte) and 3 advisors with profile and weekly goal.
- 20 fictitious clients in Barranquilla Norte/Sur, Soledad, Malambo and Galapa with real-area coordinates, a primary contact and two portfolios each.
- 4 weekly routes starting this week, assigned to the advisors, which schedules their visits.
- The two earliest past visits of each advisor done with a result; some with a commercial outcome, quote (one approved and converted to an order) and a follow-up.

Requirements: migrations applied and `DEMO_PASSWORD` (8+ characters) in `.env`; every demo user uses it, so no password is stored in the repo. Users: `admin@demo.comercial360.co`, `director@demo.comercial360.co`, `laura.martinez@…`, `andres.pacheco@…`, `camila.herrera@…` (`@demo.comercial360.co`). Running it again does nothing if the demo admin exists. Data is in `src/seeds/demo-data.ts`.

### E2E checklist (run on the deployed environment)

| # | Step | Expected |
|---|---|---|
| 1 | `POST /auth/login` as an advisor | 200 and session cookie |
| 2 | `GET /routes` as the advisor | only their route |
| 3 | `GET /visits/agenda?period=week` | visits of the week ordered by time; `GET /follow-ups/agenda` shows follow-ups |
| 4 | `PATCH /visits/:id/start`, then `PATCH /visits/:id/result` | status `VISITED`; entry in `GET /clients/:id/history` |
| 5 | `POST /visits/:id/attachments` with a photo | 201 with a signed URL that opens the photo |
| 6 | `PATCH /visits/:id/commercial-outcome` `{ quoteGenerated: true }` and `POST /quotes` with `visitId` | quote `COT-xxxx` in `DRAFT` with the right totals |
| 7 | `PATCH /quotes/:id/status` SENT → APPROVED, `POST /quotes/:id/attachment` | status changes logged; document downloadable |
| 8 | `POST /quotes/:id/convert-to-order` | order `PED-xxxx` |
| 9 | Log in as director: dashboard KPIs (HU-35), `GET /indicators/by-advisor` | numbers include the new visit/quote/order |
| 10 | `GET /reports/visits.csv?separator=semicolon` | file opens in Excel with accents |
| 11 | `POST /advisors/:id/status { isActive: false }` and log in as that advisor | 401 |
| 12 | `POST /auth/forgot-password` | email received (SES) or link in the log |

Each failure goes to GitHub as an issue with its owner.

### Local verification done

On a throwaway local database: all 20 migrations run and revert, the seed loads from scratch and is a no-op the second time, and a smoke script went through logins, advisors, role scoping on clients/routes/quotes/orders, rescheduling, not visited, commercial outcome, follow-ups, invalid attachments, the four CSV exports, indicators, password reset and the error format. S3 uploads and SES emails were not tested (no AWS credentials locally).
