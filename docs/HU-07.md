# HU-07 — Manage advisors

**Owner:** Efrain · **Epic:** E1 — Authentication, roles and advisors · **Priority:** Alta
**Source:** `docs/Comercial360_Historias_y_Reparto_v2.pdf`

> As an administrator, I want to manage advisors, to assign them routes.

## Acceptance criteria

| Criterion | Status |
|---|---|
| CRUD of ASESOR linked to a user | ✅ Done |
| Unique email | ✅ Done |
| Activate/deactivate (no physical delete) | ✅ Done |

## What was implemented

New module `src/modules/advisors/` (registered in `AppModule`).

### Data model

Table `advisors` (migration `1792720000100-CreateAdvisorsTable.ts`): `user_id` (PK and FK to `user`), `phone`, `document_number`, `zone_id`, `weekly_visit_goal` (used by HU-39), `is_active`. The advisor id **is** the user id, the same value stored as `advisor_id` in routes and visits. The migration creates an active profile for every existing user with the `ASESOR` role, and the repository reads advisors from `user` with a LEFT JOIN, so advisors without a profile still show up.

### Endpoints

| Method | Path | Role |
|---|---|---|
| `POST` | `/advisors` | Admin: creates the login account (Better Auth, role `ASESOR`) and the profile |
| `GET` | `/advisors?search&zoneId&isActive&page&limit` | Admin, Director (only their zone) |
| `GET` | `/advisors/:id` | Admin, Director (only their zone) |
| `PATCH` | `/advisors/:id` | Admin: name, email, phone, document, zone, weekly goal |
| `PATCH` | `/advisors/:id/status` | Admin: `{ isActive }` |

- **Unique email**: checked against `user` on create and update (409), besides the DB unique index.
- **Deactivation**: deletes the advisor's sessions, and a Better Auth `databaseHooks.session.create.before` hook in `auth.ts` (`isInactiveAdvisor`) rejects new sign-ins of an inactive advisor. `SessionGuard` reads the session with `disableCookieCache`, so an already open browser is rejected on its next request instead of after the 5-minute cookie cache.
- **Route assignment**: `POST /routes/:id/assign` only accepts an active advisor (a user with role `ASESOR` whose profile, if any, is active); otherwise 400 (`InvalidRouteAdvisorError`, checked through the routes module's `RouteAdvisorReaderPort`).
- Account creation goes through the `AdvisorAccountPort`, implemented by `BetterAuthAdvisorAccountAdapter`, so the password is hashed like a normal sign-up and the use cases don't depend on Better Auth.
