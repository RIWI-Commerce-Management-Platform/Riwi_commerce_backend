## What was implemented

Delivered in commit `37f4f6e` (merged in `9c14b37`).

### 1. Domain

- `catalog-item.entity.ts`: `ClientType`, `ClientStatus` and `VisitResult` (all based on `BaseCatalogItem`), plus `Potential` (with `order`) and `Portfolio` (with `description`). Each has `isActive` for deactivation instead of deletion.
- `CatalogRepository` (abstract port): `find*`, `find*ById` and `save*` for each catalog, `findAll()` and `seed(data)`.
- Errors: `InvalidCatalogTypeError`, `CatalogItemNotFoundError`.

### 2. Application

- `ListCatalogsUseCase`: all catalogs grouped in one object, including zones.
- `ListCatalogByTypeUseCase`, `CreateCatalogItemUseCase`, `UpdateCatalogItemUseCase`: dispatch on the type slug (`client-types`, `potentials`, `client-statuses`, `portfolios`, `visit-results`).
- `SeedCatalogsUseCase` with `INITIAL_CATALOG_SEED`:
  - Zones: Barranquilla Norte, Barranquilla Sur, Soledad, Malambo, Galapa.
  - Client types: Mayorista, Minorista, Distribuidor, Cadena / Supermercado, Institucional.
  - Potentials: Alto, Medio, Bajo.
  - Client statuses: Activo, Inactivo, Prospecto, Suspendido.
  - Four portfolios and six visit results.

### 3. Infrastructure

- One ORM entity per table: `client-type`, `potential`, `client-status`, `portfolio` and `visit-result` `.orm-entity.ts`. Zones reuse `ZoneOrmEntity` from the `zones` module.
- Migrations: `1792505831169-CreateCatalogsTables.ts` (unique `name` on every table) and `1792604218008-AddTimestampsToVisitResults.ts`. `clients` received its catalog foreign keys in `1792650000002-AddClientCatalogForeignKeys.ts`.
- `TypeOrmCatalogRepository.seed` is idempotent: it inserts each item only if no row with that name exists, then returns the row counts.
- `CatalogsSeedService` runs the seed on `onApplicationBootstrap` and logs (without crashing) if it fails.

### 4. Presentation

`CatalogsController` (`/catalogs`):

| Method | Path | Description |
|---|---|---|
| `GET` | `/catalogs` | All catalogs grouped, including zones |
| `GET` | `/catalogs/:type` | Items of one catalog type |
| `POST` | `/catalogs/:type` | Create an item |
| `PATCH` | `/catalogs/:type/:id` | Update name, order, description or `isActive` |
| `GET` | `/catalogs/seed/status` | Row counts per catalog |
| `POST` | `/catalogs/seed/run` | Run the seed manually |

An invalid type returns 400; an unknown id returns 404.

## Follow-up fixes

- **Admin only.** `POST /catalogs/:type`, `PATCH /catalogs/:type/:id` and `POST /catalogs/seed/run` now have `@Roles(UserRole.ADMIN)` + `@UseGuards(RolesGuard)`. `CatalogsModule` registers `UserOrmEntity`, which `RolesGuard` needs. Reads stay open to any session.
- **Validation.** `CatalogsController` applies `ValidationPipe({ whitelist: true, transform: true })`. `CreateCatalogItemDto` and `UpdateCatalogItemDto` now validate `name` (non-empty, ≤100), `order` (int ≥1), `description` and `isActive`.
- **Zones.**
  - New `PATCH /zones/:id` to rename or activate/deactivate a zone (`UpdateZoneUseCase`, `Zone.update`, `ZoneNotFoundError`).
  - `POST /zones` and `PATCH /zones/:id` are admin only and validate their DTOs.
  - A duplicate name returns 409 (before, it was an unhandled 500).
  - `GET /zones` still lists only active zones.

## Known leftover

The `InvalidCatalogTypeError` message still lists `zones` as a valid type for `/catalogs/:type`, but zones are managed through `/zones`.
